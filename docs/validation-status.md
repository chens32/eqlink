# 验收状态

截至 2026-10-18，EqLink 0.2.0 为测试版，`fullOriginalAcceptanceComplete=false`。

## 已有证据

2026-10-16 本机/隔离验收清单记录 25 项 passed、10 项 skipped、1 项 unavailable。另有四组关键恢复场景各连续五次通过，最长 21.84 秒。范围包括模式限制、部分 WFP/服务崩溃、路由竞争、物理出口、指定窗口抓包、MSI 独立迁移/事务测试，以及 ARM64 QEMU 隔离运行。

这些统计混合纯逻辑、本机和隔离测试，不能作为全产品端到端通过率。抓包结论只适用于保留窗口及被检查组件。原始失败、后续复测和证据限制均应保留。

## 当前问题

- 2026-10-18 真实网络短时检查观察到虚拟 IP ICMP 丢包及反复 `VIRTUAL_NETWORK_UNREACHABLE` / `Connected`；需要定位并补稳定性回归。
- 客户端已运行 0.2.0，但真实 k3s 仍使用旧测试镜像；当前真实网络没有覆盖新的两端完整组合。
- 私有 CA 场景下，严格 Schannel 吊销检查缺少可用撤销信息；按请求 best-effort revocation 可访问，不代表严格检查已通过。
- 原始 Burn 升级失败后通过 MSI 修复恢复，独立迁移/回滚测试通过；完整真实安装包生命周期仍待验收。

## 尚未完成的发布门槛

1. 两台独立 Windows 客户端双向 ICMP/TCP/UDP、固定地址、单设备吊销隔离。
2. Windows 全新安装、真实升级、卸载、重启、失败回滚、WFP 清理及其他 OpenVPN 配置保留。
3. BFE 不可用、Windows 防火墙配置矩阵、BFE 就绪前的启动期阻断。
4. 实际物理网卡掉线/换址/索引变化、可控 DNS 超时/换址、Meta 默认路由变化。
5. 目标原生 ARM64 k3s 的新镜像升级、设备插件/权限/seccomp、备份恢复与回滚。
6. 证书失效的真实认证故障、长时间和业务负载下的稳定性。

## CI 范围

GitHub CI 当前暂停：已移除 push/PR 自动触发，仓库工作流已停用，仅保留供后续恢复使用的手动配置。此前成功运行的结果保留为历史记录。

现有 CI 配置仅覆盖源码卫生/历史扫描、离线部署检查、跨平台核心测试和 Windows 编译。它不会部署服务端、操作生产身份、修改 WFP 或运行安装器。完整验收按 [验收清单](acceptance.md)和[执行工具](../packaging/acceptance/README.zh-CN.md)另行执行；未执行项保持 skipped/unavailable。

原始诊断、抓包和私密回滚材料留在本地受限证据目录，未纳入 Git。需要复核时由管理员按脱敏和授权范围提供。
