# Windows 指定物理出口

## 在 GUI 中选择（Windows 客户端 0.1.2）

1. 断开 EqLink 连接，以管理员身份运行 EqLink。
2. 点击主窗口的“出口设置…”，选择实际联网的有线或 Wi-Fi 网卡。列表显示名称、IPv4 和连接状态；可能包含以 Ethernet 类型呈现的虚拟网卡，直连时应选择实际物理网卡。
3. 填入该出口可以访问的 IPv4 DNS，最多 4 个，用逗号分隔。例如 `223.5.5.5`，也可填写本地路由器提供的 DNS。
4. 点击“保存设置”，返回主窗口后连接。保存时不发起连接；域名解析和可达性检查在连接时执行。

选择“系统路由（自动选择）”并保存，会删除显式网卡绑定，下一次连接使用系统路由与系统 DNS。两条外层共用同一出口；自动模式切换 UDP/TCP 时继续使用所选网卡。连接或重连期间，GUI 和后台服务均拒绝修改出口。

网卡按 GUID 保存，重启或接口索引变化后继续按同一 GUID 查找。所选网卡不存在、断开、没有可用 IPv4，或专用 DNS 解析失败时，连接报错，不回退到其他出口。刷新列表不会覆盖正在编辑的选择和 DNS；配置文件损坏时显示错误，允许管理员重新保存修复。

此功能只作用于客户端发送的外层加密流量，不需要修改服务端、k3s Service/NAT、证书或现有 `.eqlink` 设备包。它也不会将其他应用的普通流量切换到所选网卡。0.1.2 的 GUI 和后台服务应成套升级。

## 管理员配置文件

客户端可在受限目录 `%ProgramData%\EqLink\egress.json` 配置一块网卡和专用 IPv4 DNS 解析器：

```json
{
  "interfaceId": "网卡 GUID",
  "dnsServers": ["223.5.5.5"]
}
```

由管理员在断开连接时编辑，下一次连接生效。目录沿用 EqLink 的 SYSTEM/管理员权限。未配置时使用系统路由；配置无效、指定网卡不可用或初始化 DNS 失败时，连接失败并显示错误，不自动选择其他出口。

查询网卡 GUID 可使用 `.NET NetworkInterface.GetAllNetworkInterfaces()` 或有相应权限时的 `Get-NetAdapter`。使用 GUID 保存选择，避免将接口索引或 DHCP 地址写死。

指定出口后，客户端通过该网卡上的 UDP DNS 查询解析设备包内的服务器域名。DNS 套接字和连接服务器的 TCP/UDP 套接字均使用 Windows `IP_UNICAST_IF`，同时绑定该网卡的 IPv4 源地址。解析结果拒绝回环、链路本地和 `198.18.0.0/15` 假地址，DNS 不回退到系统解析器。

Hysteria 的 Windows 官方二进制没有实现 Linux 的 bindInterface 选项，因此 EqLink 为两条外层建立仅监听 loopback、仅指向当前服务器外层端口的本地转发器。转发内容是 Hysteria 或 REALITY 的加密传输，不终止 TLS，不处理 OpenVPN 明文。OpenVPN 继续只连接本机选择器。

服务器域名仍保留在加密设备资料中，Hysteria SNI、证书指纹和 REALITY 的 server name、公钥校验保持原值。解析按 TTL 刷新；刷新失败时，缓存可用于最多额外五分钟。已建立 TCP 连接不因 DNS 刷新而主动断开，后续连接使用更新后的地址。断开连接会关闭本次转发器和套接字。

该机制不修改系统 hosts、DNS、路由或其他代理的配置，不停止其他隧道。它不构成对任何 WFP/安全产品过滤行为的普遍保证，真实出口和内层直连验收仍应使用物理接口抓包。

2026-10-16 本机测试已验证：Meta Tunnel 运行期间，在物理接口 20 上解析实际服务器域名，并通过实际 Hysteria 2 和 XHTTP/REALITY 分别完成认证、取得受限健康检查的 PONG。OpenVPN/TUN、虚拟网络数据、吊销和故障恢复的通过状态需分别记录。

随后 Windows 客户端 0.1.1 已完成本机安装、设备导入及 OpenVPN/TUN 接入。仅 UDP、仅 TCP、自动模式均能访问服务端虚拟 IP；在 UDP 外层和 TCP 外层下，均通过虚拟网络上的已认证 TCP/UDP 服务完成应用数据往返。自动模式稳定后的 20 次 ping 全部收到回复。最初一次模式切换后的四包样本出现一次超时，应保留在测试记录中，不能由后续短时样本推导长期无丢包。
